# GitHub Signal

自分宛てのメンション・レビュー依頼と、自分のPRへのコメント・レビューを知らせるMac・Windowsアプリ。ウィンドウを閉じてもメニューバー／タスクトレイで動き続け、通知は「確認済み」にするまで一覧に残る。

Mac版はSwiftUI、Windows版はC#＋WPFで個別に実装している。Windows版もOS標準のトレイ通知を使い、WebViewは使用しない。

Mac版はSwiftUIとmacOS標準ライブラリだけで実装している。WebView、常駐サーバー、追加のSwiftパッケージ依存はない。GitHubとの通信時だけGitHub CLI（`gh`）を起動し、通常は2分間隔で更新を確認する。変更のないスレッドの詳細は再取得しない。

一覧は同じPR・Issueを1件にまとめ、開くと個別のコメントやレビューを確認できる。メニューバーにもPR・Issue単位の未確認件数を常時表示する。スヌーズ中も件数に含め、0件のときも「0」を表示する。

承認されたレビューは一覧で`Approve`と表示する。タイトルや「GitHubで開く」からブラウザに引き渡せたら確認済みになる。URLコピーだけでは確認済みにしない。

## Windows版

[Releases](https://github.com/zimathon/github-notification/releases/latest)から`GitHubSignal-<version>-windows-x64.zip`をダウンロードし、ZIP全体を展開して`GitHubSignal.exe`を起動する。Windows 11 x64向けで、.NETランタイムを同梱しているため.NETの事前インストールは不要。コード署名は行っていない。

接続前にPowerShellで次を実行する。

```powershell
winget install --id GitHub.cli -e
gh auth login --hostname github.com --web
```

- アプリの「開始」で取得を始める。閉じるボタンでは終了せず、タスクトレイに常駐する。「終了」で停止する。
- 同じPR・Issueを1行にまとめ、トレイに未確認件数を表示する。0件ならGitHubアイコン、100件以上なら`99+`になる。
- 組織・リポジトリ・種類の表示フィルタ、検索、GitHubを開く、URLコピー、PR単位の確認済み・1時間のスヌーズに対応する。
- 設定で通知対象の組織、取得間隔、再通知間隔、Bot通知を変更できる。表示フィルタは通知対象に影響しない。
- Windowsのトレイ通知はまとめて1つ表示し、クリックで一覧を開く。OSの通知設定や応答不可モードで抑制される場合がある。「テスト通知を送る」で確認できる。
- 新版の確認は起動時と、その後ウィンドウを開いた際に前回から24時間以上経過していれば行う。Windows用ZIPがある新版だけを案内し、ダウンロードページを開く。差し替えは手動で行う。

Windows版のデータは`%LOCALAPPDATA%\GitHubSignal\inbox.json`に保存する。認証トークンは保存しない。Mac版とのファイル共有には対応しない。GitHub CLIは`%ProgramFiles%\GitHub CLI\gh.exe`または`%LOCALAPPDATA%\Programs\GitHub CLI\gh.exe`を使う。`GH_TOKEN`や独自の`GH_CONFIG_DIR`は使用しない。

Windows初版は、透過設定・投稿者画像・ログイン時の自動起動には未対応。通知バナーの表示と実アカウントの接続は利用するWindows PCで確認する必要がある。

### Windows版をビルドする

.NET 10 SDKを使用する。アプリのビルド・起動にはWindowsを使う。CoreのテストはMacでも実行できる。

```powershell
dotnet run --project windows/GitHubSignal.Tests -c Release
./scripts/package-windows.ps1
./dist/windows-x64/GitHubSignal.exe --demo
```

GitHub Actionsの`Windows`ワークフローでもCoreの回帰テスト、WPFのビルド・画面生成テスト、配布ZIPの作成を行う。通知判定の一部はMac版と同じJSONテストデータで検証する。デモでは通信・OS通知を行わず、操作による保存は一時フォルダーに限定する。

以下はMac版の使い方。

## Mac版をReleasesからダウンロードする

[最新版のダウンロード](https://github.com/zimathon/github-notification/releases/latest)から`*-macos-arm64.zip`を取得し、展開した`GitHub Signal.app`をアプリケーションフォルダへ移動して起動する。

配布版はApple Silicon搭載Mac向けで、macOS 13以降が必要。GitHubへの接続には、別途GitHub CLI（`gh`）をインストールしてログインしておく。

配布版はアドホック署名で、Developer IDによる署名・公証は行っていない。macOSのセキュリティ設定によっては、起動が制限される場合がある。

起動時と、その後24時間ごとにアプリの最新版を確認する。新しい版があると一覧とメニューバーメニューに表示し、「ダウンロード」からReleasesを開ける。メニューの「アプリの更新を確認」で手動確認もできる。ダウンロードとアプリの差し替えは手動で行う。

更新確認には公開APIを使い、GitHubの認証情報は送信しない。自動確認に失敗しても通知の取得は継続し、エラーは手動確認時だけ表示する。デモ表示中は更新を確認しない。

## ソースからビルドする

macOS 13以降、Swift 5.9以降を含むXcodeまたはCommand Line Tools、Homebrew版GitHub CLIが必要。ビルド後の接続手順は「通知を始める」を参照。

```sh
bash scripts/test.sh
bash scripts/build-app.sh
open "dist/GitHub Signal.app"
```

配布用のZIPとSHA-256チェックサムを作るには、`bash scripts/package-release.sh`を実行する。実行したMacのCPUに対応するアプリが`dist/`に出力される。

GitHubに接続せず画面を確認する場合は、通常版を終了してから次を実行する。デモはサンプル表示だけで、通信・通知・データ保存を行わない。

```sh
open "dist/GitHub Signal.app" --args --demo
```

## 通知を始める

1. `gh`をまだ使っていない場合は、ターミナルで次を実行する。

   ```sh
   brew install gh
   gh auth login --hostname github.com
   ```

2. アプリの「通知を開始」を押す。macOSの通知許可を求められたら許可する。
3. 設定画面の「テスト通知」で、バナーが届くことを確認する。

初回は直近24時間に更新された通知が対象になる。以後は取得位置を保存し、アプリを再起動しても続きから確認する。

Notifications APIには`notifications`または`repo`の権限が必要で、非公開PRの詳細取得には`repo`が必要になる。権限不足のときは、必要な権限だけを`gh auth refresh --hostname github.com --scopes notifications`などで追加する。組織のSSO認可が必要な場合もある。アプリ自身は権限変更を行わない。詳しくは[GitHubのNotifications API仕様](https://docs.github.com/en/rest/activity/notifications)を参照する。

## 通知を確認する

一覧のタイトルか「GitHubで開く」を押すと、ブラウザで該当するPR・Issueを開く。右端の矢印で個別の更新を展開できる。各更新の外部リンクボタンからコメントを開き、「…」メニューで確認済みやスヌーズを選べる。本文プレビューではMarkdown記号やBotの管理用コメントを取り除き、「元の本文を見る」で保存された本文を確認できる。

| 操作 | 動作 |
| --- | --- |
| GitHubで開く | ブラウザに引き渡せたら確認済みにする。一覧行からならPR全体、個別の更新からならその通知だけが対象 |
| 確認済み | アプリ内の未確認一覧から外す。GitHub側の既読は変更しない |
| 1時間後 | その通知の再通知を1時間止める。新しいコメントは別の通知として届く |
| 未確認の再通知 | 既定は30分。設定で15分・1時間・なしに変更できる |
| 停止 | GitHubの取得と再通知を止める |

一度に4件以上が通知対象になった場合は、まとめて1つのバナーを出す。個別の内容は一覧で確認できる。Botによる投稿も既定で通知する。Botの通知を無効にしても一覧への保存は続ける。

## 組織を絞ってプッシュ通知を受け取る

通知一覧の上部にある組織・リポジトリの選択欄は、表示だけを絞り込む。選択は再起動後も保持し、種類や検索とも併用できる。この表示フィルタはプッシュ通知の対象を変更しない。

通知対象を変えるには、設定の「通知対象の組織・ユーザー」に`org-a, org-b`のように名前を入力して「適用」を押す。複数指定でき、空欄にするとすべてが対象になる。個人所有のリポジトリは、その人のGitHubユーザー名で指定する。

フィルタは一覧、メニューバーの件数、Macへのプッシュ通知、再通知に共通で適用する。対象外の通知はローカルに保持するため、フィルタを戻すと再び表示される。GitHubからの取得自体は継続する。

プッシュ通知はmacOSのバナーと音を使う。許可されていない場合はアプリの「通知を許可」を押す。すでに拒否している場合は「通知設定を開く」からGitHub Signalの通知を許可し、設定内の「テスト通知」で確認する。スマートフォンへの通知には対応していない。

## 初版の対象と制約

- `github.com`の1アカウントに対応する。GitHub Enterprise Server、複数アカウント、チーム宛てのメンション・レビュー依頼には未対応である。
- 対象はIssue・PR本文とコメント内の個人宛て`@username`、PRの行コメント・レビュー本文、自分のPRへの他者のコメント・レビュー、個人宛てレビュー依頼である。自分自身の投稿は除外する。
- メンションは本文の文字列で判定する。GitHubのMarkdown解釈や通知対象判定を完全には再現しない。
- GitHubの通知一覧が取得元である。GitHub側で通知が発生しない更新、削除された通知・コメント、権限のないリポジトリは拾えない。レビュー本文の編集だけを追跡する機能はない。
- レビュー依頼は履歴上のイベントとして保存する。その後依頼が取り消されても、確認済みにするまで一覧に残す。
- Macのスリープ中・アプリ終了中は取得も通知も止まる。再開後に取得を再開するが、集中モードなどmacOS側の設定でバナーが抑制される場合がある。ログイン時の自動起動は初版には含まない。
- 同期では30分の重複取得期間を設け、イベントIDで重複排除する。GitHubのAPI反映遅延やページング中の更新について、取りこぼしゼロを保証するものではない。

## 接続や保存に失敗したときは

エラーは一覧の上部に表示する。取得に失敗したスレッドは再試行用に保存し、原則5分後に再試行する。保存データが壊れている場合や書き込めない場合は、上書きを避けて同期を停止する。

認証を確認するには`gh auth status --hostname github.com`を使う。アプリはHomebrew標準の`/opt/homebrew/bin/gh`または`/usr/local/bin/gh`を使用する。独自の`GH_CONFIG_DIR`や環境変数で渡したトークンには対応しない。アカウントが変わった場合は同期を止めるため、元のアカウントに戻して再開する。

ローカルデータは`~/Library/Application Support/GitHubSignal/inbox.json`に保存する。リポジトリ名、通知本文の冒頭500文字、確認状態などを含む。トークンは保存しない。未確認の通知は保持し、確認済みの履歴は原則7日を過ぎると削除する。本文メンションの確認済みIDは、古いPRが更新された際の重複通知を防ぐため保持する。

不具合を調べる際は、画面上のエラーと再現操作を記録する。トークンや非公開リポジトリの本文を、そのまま外部へ共有しない。

## 実装と検証

`Sources/NotificationCore`に取得・判定・保存処理、`Sources/GitHubSignal`に画面とmacOS通知処理を置いている。テストはネットワークやGitHub認証を使わず、メンション判定、再依頼、重複排除、スヌーズ、永続化、取得失敗、ページングを確認する。

実アカウントでの取得とmacOSバナーの表示は、接続後の実機確認が必要である。
